## [S1] Problem

The fork tracks upstream's kernel, packages, and docs, but its history is an orphan import: upstream commits can never merge, so each upstream release must be replayed as a content-level tree merge with the fork's divergence areas re-applied by hand. Upstream has moved to `0.2.3-alpha.2`, and every fork surface that touches changed upstream code — the client UI packages, the generated catalogs, the gates, the CLI identity, the desktop shell's exclusions — needs the delta without losing the fork's identity or features.

## [S2] Design

### S2.1 — Merge method

`git merge-tree --write-tree --merge-base dsh-v0.2.2-rc.1 master dsh-v0.2.3-alpha.2` computes the whole content merge in one pass; the result is materialized onto `resync/upstream-0.2.3-alpha.2`, conflicts are resolved in the tree, and the branch lands as a single-parent commit. Non-collision paths take their winning side automatically. The 451-path collision set is the hand-workload: 241 modify/delete paths where the fork had deleted the tree resolve to deleted, and 208 modify/modify paths resolve by content.

### S2.2 — Collision resolution rules

1. Paths carrying a `PRISM-DIVERGENCE` marker: three-way content merge using the `dsh-v0.2.2-rc.1` blob as merge base, re-applying the marker's instruction onto upstream content.
2. Fork-side changes without markers (README pairings, generated catalogs, bundle rows, spec pages): content merge, then re-run the owning generator so generated files land on upstream's generator output plus fork inputs.
3. `.github/workflows/*`: the fork keeps only its three Prism desktop pipelines; every imported upstream workflow resolves to deleted, including upstream's newly added ones (A10).
4. Upstream deletions: take the deletion; re-point any fork reference left dangling (bundle rows, catalogs, tsconfig aliases).
5. `pnpm-lock.yaml`: take upstream's, then re-reconcile with `pnpm install` after the fork's workspace additions are back in place.
6. Alias rows and workspace dependencies are validated against the merged tree: a row whose target package no longer exists is dropped, and the generated alias region is regenerated by `gen-tsconfig-paths`.

### S2.3 — Version fields and generated artifacts

All workspace `package.json` version fields move to `0.2.3-alpha.2`, including the fork's own `@prism/*` packages; `plugins/*` keep their own versioning scheme but their `@deepseek-ai/dsh-*` exact pins move to `0.2.3-alpha.2` so the exact-version gate installs them. After the merge: `pnpm install`, then `gen-tsconfig-paths`, `gen-cordis-catalog`, `gen-tool-catalog`, and the other owning generators when their inputs changed.

### S2.4 — Divergence replay

A1 (Tauri desktop replaces upstream's Electron shell; `apps/desktop-host/**`, `apps/desktop-publisher/**`, and the Electron notes stay deleted), A4 (the `@electron/osx-sign` and `app-builder-lib` patch rows and files stay deleted), A8 (the CLI install identity stays `prism-agent` / bin `prism`), and A10 (the workflow suite stays deleted) are re-applied on the merged tree; the divergence index records the new anchor.
