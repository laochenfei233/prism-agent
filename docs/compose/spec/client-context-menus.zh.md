# 客户端右键菜单

[English](client-context-menus.md) | 中文

## [S1] Problem

客户端的所有界面目前都弹出浏览器默认右键菜单。会话列表、项目（工作区）标题、对话文字、输入框与文件树都没有二级点击入口，而这些位置想做的事情大多在产品里已经存在。

## [S2] Design

**S2.1 — 一个指针锚定的菜单原语。** `@deepseek-ai/dsh-client-ui-primitives` 增加 `ContextMenu`，它是既有 `Menu` 的薄封装：调用方给出指针位置，它提供 `getAnchorRect` 并阻止浏览器菜单。键盘走查、Escape、外部按下关闭与视口内收边仍由 `Menu` 负责。

**S2.2 — 会话行复用既有动作列表。** 在会话行上二级点击打开的，正是 "..." 菜单所用的 `sidebar.workspaces.session.menu.item` 条目，两个界面因此不会分叉。`ui-workspace` 在既有条目旁注册新的内置条目：在资源管理器中打开（`session.openWorkspacePath` 的 `action: 'reveal'`）、复制路径（`cwd`）与前往配置（`settings.open` 命令）。没有后端支撑的条目直接不显示而不是置灰：移到分组（会话属于其 `cwd` 解析到的工作区）、复制任务路径与复制日志路径（客户端从不获得会话存储路径）、标记未读（不存在持久未读事实）。

**S2.3 — 项目行有自己的菜单。** 新建会话、置顶、置底、在资源管理器中打开、重命名、删除，以及置灰的导出占位。不显示"复制"：一个目录只注册一个工作区，没有可复制的实体。不单列"查看文件"，因为文件树以会话为作用域；在资源管理器中打开已覆盖浏览该目录的意图。

**S2.4 — 对话文字按选区行事。** 在消息上二级点击时，有选区就复制选区，否则复制整条消息。"添加到当前任务"通过公开的 `inputActions` 接口把文字按引用（每行前缀 `>`）插入当前输入框。"在辅助对话中提问"在同一工作区新建会话并预填引用；它不发送，因此不会在没有二次确认的情况下触达模型。

**S2.5 — 输入框菜单就地编辑。** 撤销、重做、剪切、复制、粘贴、删除、全选派发输入框自己的 Lexical 命令。粘贴通过 `navigator.clipboard.readText()` 读取剪贴板；被拒绝的读取给出提示，要求改用键盘快捷键，而不是静默失败。

**S2.6 — 文件行通过 Host 打开。** 预览打开右栏既有的文档页。打开与打开方式调用 `session.openWorkspacePath`，处理程序列表来自 `session.workspacePathApplications`。两个复制项使用文件树的绝对路径与树根。

**S2.7 — 所有文案归字典所有。** 新键放在各自包的 `locales.ts`；界面不出现字符串字面量。

**S2.8 — 命令式调用。** `ShortcutsService` 暴露注册表已有的 `invoke(id, context)`，菜单行因此可以运行 `settings.open` 之类的已注册产品命令。

## [S3] Scope

- 范围内：五个右键菜单、共享原语、新的会话菜单条目、设置命令的 invoke，以及它们的测试。
- 范围外：持久未读状态、跨工作区移动会话、暴露会话存储/日志路径、复制工作区、项目导出，以及改动 "..." 菜单既有的排序号。
