## [S1] Problem

Two scheduled-task systems coexist in the tree: cron, imported early in the fork (`ctx.cron` in `packages/cron/cron`, the model tools in `packages/cron/tool-cron`, the Remote controller in `packages/api/cron-controller`, the task panel in `packages/client/ui-cron`, plus the `apps/cli/config/examples/cron/cordis.yml` overlay), and upstream 0.2.x schedule (`packages/schedule/schedule` + `tool-schedule` + `client/ui-schedule`, the "Automation tasks" page). In the Web composition `ui-schedule` is enabled (`packages/bundle/web-app/cordis.patch.yml`), `ui-cron` sits parked behind `disabled: true` in the same file, and the whole cron stack takes effect only through an explicit overlay. Two entry points, two storage domains, and two sets of documents and directory rows double the reading and maintenance cost; the cron backend packages sit in the tree without default-composition wiring, neither landed nor gone. Decision: consolidate on upstream — keep schedule, retire cron entirely.

## [S2] Design

### S2.1 What stays: schedule already covers cron's vocabulary

- schedule's `CronScheduleRecord` (`packages/schedule/schedule/src/types.ts`) supports five-field Vixie cron expressions with an explicit IANA zone (`CronInput { expression, time_zone }`) natively, alongside after/at/every/daily/weekly rules. Everything cron was for — five-field expressions, time zones, prompt delivery into a Session, tasks surviving restarts — is covered.
- schedule's delivery targets (an existing Session, one Session created and reused, a new Session per delivery) correspond to cron's `CronExistingSessionTarget` / `CronNewSessionTarget`.
- schedule and its UI keep their current behavior in the Web composition; nothing about them changes.

### S2.2 What retires: the whole cron chain is deleted

Dependency check: only `tool-cron` and `cron-controller` depend on `@deepseek-ai/dsh-cron`, so the package can be removed whole. Deletion list:

- Packages: `packages/cron/**` (cron, tool-cron, and the group README trio), `packages/api/cron-controller/**`, `packages/client/ui-cron/**`.
- Composition: the `apps/cli/config/examples/cron/cordis.yml` overlay; the `dsh-api-cron-controller` and `dsh-cron` dependency rows in `apps/cli/package.json`; the `ui-cron` row in the web-app patch and its dependency row in `packages/bundle/web-app/package.json`.
- tsconfig: the cron aliases in `tsconfig.base.json` and the reference rows in `tsconfig.host.json` and `tsconfig.client.json`.
- typert: deleting the packages withdraws the face-purity registrations, so the `@typert service cron` marker and the `./typert` export that the resync added no longer exist.
- Documents and catalogs: the `docs/subsystems/cron.md/.zh.md/.i18n.yaml` trio and the cron row in `docs/subsystems/README(.zh).md`; the `ctx.cron` / `ctx.cronController` rows and mermaid nodes in `docs/capability-seams(.zh).md`; the cron/cronController SERVICE_PAGE rows in `gen-cordis-catalog` and the cron SERVICE_ROLES row in `gen-doc-graphs`; regenerate `docs/config-catalog(.zh).md`.
- Snapshots: the cron tool surface appears in `snapshots/sdk/desktop-ptc-context*/system-prompt.expected.md`, `snapshots/web/{ptc-round,ptc-round-scoped,optional-string-editor,official-subagent-bundle}/system-prompt.expected.md`, and `snapshots/session/meeting-minutes-list/session.v4.jsonl`; update each. `snapshots/web/schedule-catalog/` belongs to schedule and stays.
- Divergence index: the A7 row of `docs/compose/spec/fork-upstream-divergence(.zh).md` changes cron from "import in progress" to "retired (see this spec)".

### S2.3 Data disposition: no migration, no deletion

cron was enabled only through an opt-in overlay and the default composition never included it, so few real deployments are affected. The stored `cron` domain (`CronJob` v1 records) keeps its bytes on disk and is not cleaned up, which follows the rule that a committed generation is never deleted; with the code gone those records become orphans no reader opens. The upgrade guide states that a deployment that used the cron overlay must rebuild its tasks in schedule (the Automation tasks page).

A one-time conversion at startup (`CronJob{expression, timeZone, prompt, target}` to a schedule `kind:'cron'` record) was considered and rejected: cron's per-task `agentPreset`/`permissionPreset`/`model`/`overlapPolicy`/`misfirePolicy` have no matching slot in schedule, so the conversion would lose them; and it would leave the fork holding cron's decoding knowledge long after retirement, which is what retirement exists to end.

### S2.4 Documentation

The upgrade guide gets a breaking entry (cron removed, rebuild through schedule); the README trio disappears with its packages; `docs/persistence-changes` and the persistence catalog/formats record that the `cron` domain retired (records kept, no longer read).
