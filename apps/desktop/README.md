# dsh-desktop — Prism Agent Desktop Client

English | [中文](README.zh.md)

<!-- PRISM-DIVERGENCE: replay list in docs/compose/spec/fork-upstream-divergence.md (S2). -->

A Tauri 2 desktop shell that embeds the dsh web UI in a native window, with a bundled Node runtime and a pruned dsh distribution: works out of the box, stays running when the window closes (tray resident), and restarts automatically if the service crashes. Prism uses its own bundle id (`ai.prism.agent.desktop`) so its WebView2 and browser-session storage do not overlap with DeepSeek Harness Desktop. **It does not modify any upstream `packages/` / `apps/cli` code.** The four agent presets (`standard` / `code` / `minimal` / `cordis`) come from upstream unchanged.

## Architecture

```
src-tauri/            Rust shell
  src/dsh_runner.rs   dsh child-process lifecycle: spawn `dsh web --port 3081 --no-open`, port health probe, crash auto-restart (does not race when dsh-plugin restarts itself)
  src/tray.rs         tray residency: closing the window hides it; only tray Quit ends the process tree
  src/quit.rs         installer-requested exit: --quit signals the running shell, which removes its tray icon
  src/setup.rs        first-launch profile seeding: preinstall the bundled default plugins into the web profile (patch + bundle layers)
  src/update.rs       in-app updater state: GitHub-Releases-only checks, progress events, and the install handoff to the NSIS installer
  installer-template.nsi  vendored NSIS template (tauri-cli-v2.11.4) with the upgrade default flipped to an in-place overwrite; re-sync when the pinned CLI version changes
ui/dist/              shell frontend (pure static, no build): index.html full-window iframe + error banner
scripts/bundle-runtime.mjs  pack Node runtime + pnpm-deployed dsh closure + local plugins → runtime/
runtime/              packaging output (not committed; generated by CI; tauri.conf.json maps it as bundle resources)
```

Port and authentication contract: in-shell `dsh web` listens on `127.0.0.1:3081` by default; if that port is taken by another process, the shell scans upward for a free port (from 3082) and passes `--port`. The Rust shell reads the tokenized launch URL printed by `dsh web`, exposes it through `dsh_status` and `dsh://launch-url`, and the frontend uses that URL so the loopback browser session can mint its cookie before loading the clean origin. Because the shell embeds the UI in a cross-site iframe, the desktop bundle changes that cookie to `SameSite=None; Secure`; the loopback Host/Origin trust checks still gate the API. CLI `dsh web` still defaults to 3080. `/api` (including `host.openPath`, WebSocket downlink, SSE) is entirely served by dsh itself; the shell does not reverse-proxy. The shell does not render a top navigation bar — the interface is entirely the dsh UI; shell and iframe only exchange host-bridge messages (`source: 'dsh-desktop-host'`): interface readiness, native notifications, external links, and the allow-listed updater relay.

Startup presentation: the window opens under a shell-owned splash. The bridge that `scripts/bundle-runtime.mjs` injects into the served page asks the shell to hold that splash, then reports when the client plugins activated and the application took the mount point — later than the frame's load event. A page without that bridge (a dev runtime seeded from an unpatched dist) keeps the load-time reveal, and a bridge that never reports falls back to the shell's 20-second bound.

Hub adoption: the shell records the hub it starts in `$DSH_HOME/desktop-server.json` (port, launch URL, pid, and the CLI entry point with its length and modification time) and, on the next start, adopts that hub instead of spawning a second one whenever the record names this build's entry point and a loopback `GET /?token=…` on its port is still answered with 303. An adopted hub skips `ensure_home_node_modules`, `ensure_default_plugins`, port selection, the spawn, and the whole `dsh web` boot; `dsh_status`, `dsh://ready`, and the frontend's authenticated load behave exactly as for a spawned hub, and "Restart service" re-verifies the record and ends the adopted hub by pid so the supervisor replaces it. A record is dropped only once the hub it names stops serving, so a hub that outlives the shell stays adoptable by the next start. Before adopting a hub, and again before every cold spawn, the shell ends the other hubs this product owns — the installed closure's or this checkout's, never another harness build's — so one home has one writer; debug builds skip that sweep, so a dev shell cannot end the installed app's hub.

Single instance: every build registers the desktop single-instance plugin before every other plugin. Launching the executable again shows, unminimizes, and focuses the running main window, then exits before it creates a second shell, tray icon, or hub, so repeated launches — `tauri dev` included — cannot run separate agents against the same Prism window. The Linux backend requires a D-Bus session bus, which desktop sessions provide. An upgrade does not remove dead notification-area entries left by earlier forced kills; hover over them in the hidden-icons flyout or restart Explorer.

Web permissions: the dsh UI runs on the loopback origin inside the frame, so the shell grants that frame what the desktop client can use and nothing more. `ui/dist/index.html` delegates `microphone`, `camera`, `display-capture`, `geolocation`, `notifications`, `autoplay`, `fullscreen`, `clipboard-read`, and `clipboard-write` to the iframe — a cross-origin frame is refused before WebView2 is asked at all — and `src-tauri/src/lib.rs` answers WebView2's `PermissionRequested` with `Allow` for the microphone, camera, geolocation, notifications, clipboard read, autoplay, and file read/write. WebView2 denies every kind the host leaves unanswered and never prompts on its own, which is what made recording fail with "Permission denied"; MIDI, sensors, and window management stay unanswered. Screen capture has no permission kind in this WebView2 SDK, so the frame's `display-capture` delegation is the whole grant. Tauri exposes the `core`, `opener`, `notification`, `dialog`, `fs`, and `clipboard-manager` defaults to the shell window. The main window sets `dragDropEnabled: false`, without which the platform webview swallows HTML5 drop events and the UI's own attachment drag and drop never fires; file and image upload need no shell permission at all, because the UI opens a file input and uploads over `/api`.

## Development

Prerequisites: Node ≥ 22.19, pnpm ≥ 11, Rust ≥ 1.77, Tauri CLI (provided as a devDependency of this package).

```sh
pnpm install                # workspace dependencies
pnpm run build              # produce lib and apps/web/dist (static frontend for dsh web)
pnpm tauri dev              # from apps/desktop; dev mode uses PATH node + apps/cli/lib/bin.js
```

Dev mode needs built CLI artifacts (`pnpm run build`); you can also override runtime resolution with environment variables:
`DSH_DESKTOP_NODE` (node executable), `DSH_DESKTOP_DSH_BIN` (dsh CLI entry), `DSH_DESKTOP_PLUGINS_DIR` (local plugins directory).

Dev shells that are force-killed — for example from a worktree or target path different from the installed build — can still leave a tray entry, because a killed process never reaches the exit path that deletes it. Hover over the duplicate in the hidden-icons flyout or restart Explorer to clear it; the installed build is unaffected.

## Building a release

```sh
pnpm run build              # repository artifacts
node scripts/bundle-runtime.mjs --platform win   # win|mac|linux; generates runtime/
pnpm tauri build            # package installers (runtime/ is bundled as resources)
```

The Windows NSIS installer is current-user only: it installs below `%LOCALAPPDATA%\Prism Agent`, needs no elevation, selects English, Simplified Chinese, or Traditional Chinese from the OS language, creates a `Prism Agent` Start Menu shortcut, and uses the branded installer header/sidebar images in `src-tauri/icons/`.

Upgrading does not uninstall first. The stock Tauri reinstall page preselects "uninstall before installing" on upgrades, which runs the old uninstaller and its wizard every time; the vendored template (`installer-template.nsi`, wired through `bundle.windows.nsis.template`) swaps that default, so a double-click upgrade overwrites the self-contained install directory in place — the same thing `/UPDATE` does — and the clean uninstall remains the second choice on the same page. When the pinned `@tauri-apps/cli` version changes, re-vendor the template from the matching upstream tag and re-apply the marked delta; the file header names the source tag.

The installer and uninstaller first ask the shell to leave: when a `prism-agent.exe` process is running from the install directory, the hooks start it with `--quit` and poll for up to 15 seconds. The flag signals that shell and it exits through Tauri's normal exit path, which deletes the tray icon; a forced kill by exact executable path then runs as the fallback and finds no process on a clean update. An installation whose shell predates the flag — including the `dsh-desktop.exe` build from before the rename — cannot be asked to exit: quit it from the tray before installing, so the hooks find no process and skip the forced kill, which would leave dead notification-area entries.

CI (`.github/workflows/desktop-release.yml`) runs the same flow on a three-platform matrix and uploads to GitHub Release; trigger with a `v*` tag or manual dispatch.

## In-app updates

The shell embeds `tauri-plugin-updater`, and the update source is fixed to this repository's GitHub Releases: `tauri.conf.json` pins the endpoint to `https://github.com/laochenfei233/prism-agent/releases/latest/download/latest.json`, and there is no custom-source override. The URL resolves against the newest published release, which carries the `latest.json` manifest and the signed installer; the plugin verifies the minisign signature before installing. Draft releases are invisible to the endpoint — publish the release to serve updates.

Release prerequisite: updater artifacts require the minisign private key. The public key is committed in `tauri.conf.json`; keep the private key outside the repository (this machine: `~/.prism-updater/prism-updater.key`, no password) and expose it as `TAURI_SIGNING_PRIVATE_KEY`:

- CI: set the repository secret `TAURI_SIGNING_PRIVATE_KEY` (leave `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` empty) so `desktop-release.yml` produces the `.sig` files and `latest.json`.
- Local: with `bundle.createUpdaterArtifacts` on, `pnpm tauri build` needs the same variable (`$env:TAURI_SIGNING_PRIVATE_KEY = Get-Content ~/.prism-updater/prism-updater.key`); `pnpm tauri dev` does not.

Until the first release carrying updater artifacts is published, in-app checks fail with the source-unreachable state; that is expected.

Flow: the shell checks once, 30 seconds after launch — silent, with failures recorded in `update-state.json` under the app data directory and shown in the About section. Every transition emits `prism://update-state`; the injected host bridge forwards it into the UI, where the settings header shows the compact indicator and sidebar badge, and the About section (the bundled `prism-about` plugin) renders the full page. The bridge exposes exactly three commands to the frame (`prism_update_state`, `prism_check_update`, `prism_install_update`) — a deliberate allow-list, since the frame is web content. Installing downloads first with the runtime still running, then stops the dsh child, then hands off to the NSIS installer: the same silent `/UPDATE` over-install the hooks already serve, after which the installer restarts the app.

## First launch

- Default preset: `standard` (the upstream default; switch it by setting `agent-presets.config.default` in `~/.prism/profiles/web/cordis.patch.yml`)
- Bundled local plugins: `aegis`, `dsh-agent-progress`, `dsh-tauri`, `prism-about`, `prism-guardrails`; `prism-meeting` ships with the experimental voice-input bundle for speech-backed meeting minutes; `dsh-plugin` is the plugin center/market and `dsh-win-terminal-inspector` is the Windows terminal inspector
- Optional plugins (install through the plugin center): `dsh-better-sidebar`, `dsh-notification`, `dsh-session-context-menu`, `@xmanrui/dsh-im` (WeCom/Feishu/DingTalk/WeChat/QQ and 9 channels), `dsh-lark`, `dsh-qqbot`, `dsh-vision-router`, `graph-memory`, `aegis`

Plugin install/update/uninstall all go through official dsh mechanisms (`dsh plugin` / the dsh-plugin center); the runtime ships pnpm from the same version family.
